01 / Industrial workflowReal PLC test pending

Nova Control

I built a Windows application that organizes concrete-plant work while keeping machinery control with the operator and the PLC.

2,635 automated tests7 workflow sections3 PLC connection options

How I built it: I mapped the workflow, converted plant requirements into software rules, used AI coding tools to add three PLC connection options, and ran repeated tests and agent audits.

Read full project details

The problem

Concrete recipes, customer orders, trucks, raw materials, and production records must stay consistent. The application also exchanges information with the plant controller, so its limits must be clear and testable.

What I built

A seven-section Windows application for recipes, orders, trucks, materials, production records, concrete passport PDFs, activity history, and backups. It supports Delta controllers and an older Omron setup, with a simulated controller for testing without plant hardware.

Safety boundary

Nova sends the recipe, requested amount, and cycle information to the PLC. The operator checks the information and starts production from the plant touchscreen. Nova reads and saves the results; it cannot start, stop, empty, reset, or directly control the machinery.

Testing and status

The 2,635 automated tests cover screens, calculations, saved data, unusual inputs, controller connections, restarts, and simulated production. The software for version 2.0.4 is complete; testing with the real Delta PLC and plant operator is still pending.

02 / Browser behaviorLive

Fake Discount Bulgaria

I built a Chrome and Edge extension that saves the prices users actually see and shows whether the current offer looks good compared with that history.

20 stores5 result states2 languages

How I built it: I defined the result states and store-specific rules, used saved product pages for repeatable testing, investigated incorrect matches, and published the extension.

Chrome Web Store ↗
Read full project details

The problem

A crossed-out price does not show whether a discount is genuinely good. The extension builds a personal price history from the product pages a user visits instead of accepting the shop's reference price at face value.

What I built

The extension records one EUR price per day across 20 Bulgarian stores. It shows a price-history chart, five result states, a searchable product history, target-price indicators, barcode capture, backup and restore, and Bulgarian and English interfaces.

Store differences

Each retailer presents prices differently. The extension handles pages that update without a reload, EUR and BGN displays, unavailable products, manufacturer prices, legal 30-day reference prices, and unrelated suggested products. It sends observations to an online database when possible, while the result shown to the user is calculated locally.

Testing

I used Claude Code, saved copies of real product pages, and repeated reviews to test extraction rules. The main challenge was identifying the correct product price without accidentally using a reference price or a nearby product recommendation.

03 / Rule consistencyLive

Малки Подаръчета

I built a website that turns custom handmade-gift requests into a clear order with products, quantities, personalization, delivery details, and price checks.

81 pages60 combinations32 galleries

How I built it: I mapped the ordering rules, checks, sharing, and discounts, then used AI coding tools and complete ordering-flow tests to build and refine the site.

Live website ↗
Read full project details

The problem

Custom orders were discussed through Facebook and Viber messages, where quantities, dates, personalization, and delivery preferences could be missed or misunderstood.

What I built

The website contains 81 pages and a three-step ordering flow. Six event types and ten themes create 60 combinations. Customers can choose from six configurable gift types, 16 variations, 19 ready-made products, and 32 multi-image project galleries.

Order checks

The cart is saved in the browser, stays in sync between tabs, can be shared through a link, and checks saved prices against the current catalogue. It also handles volume discounts, delivery preferences, urgent orders, and warnings for events less than two weeks away. The final order is sent to the workshop by email.

Testing

The main challenge was keeping orders reliable without its own database, server, or online payment system. I tested old prices, missing products, broken shared links, duplicate items, and incomplete personalization so they could not silently change an order.

SIMA-MA

I built a Bulgarian and English website that presents an industrial manufacturer's equipment, completed work, contact options, and required EU project documentation.

12 content pages2 languages7 gallery categories

How I built it: I organized the content, defined the Bulgarian and English structure, used AI coding tools to build it, and checked accessibility, responsive behavior, and language consistency.

The problem

SIMA-MA needed a clear Bulgarian and English web presence for local and international buyers, using incomplete source material from several areas of the business.

What I built

The site has 12 Bulgarian and English content pages, a custom background animation, a project gallery organized into seven categories, a keyboard- and swipe-friendly image viewer, and a dedicated EU project area with grouped procurement documents.

Contact and visibility

The contact form checks required information, blocks simple spam, asks for privacy consent, and shows clear errors. Google Maps loads only after consent. The site also includes separate language URLs, search metadata, caching, and security settings.

How I worked

I used Claude Code and Codex with straightforward HTML, CSS, and JavaScript files. The main challenge was keeping both language versions, the large image gallery, accessibility, and mobile behavior consistent while the source content evolved.
